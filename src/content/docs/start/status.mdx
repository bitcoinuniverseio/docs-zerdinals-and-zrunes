### Which of these rows can go out of date

Every row is tied to the recorded verification time. Deployments, chain
progress, indexing, wallet qualification and infrastructure availability can
change these results. Check the product's current operation state before
creating, signing or paying for an order.

Checking it yourself takes one request, against the same public endpoint this
page is generated from:

```bash
curl -s https://zrunes.io/api/ready
```

`"ok": true` means the record is readable right now. Anything else means it is
not, and the product will tell you the same thing in plain words when you open
it. The indexer's own view is at the second endpoint:

```text
https://zrunes.io/idx/zcash-metaprotocols/status
```

## What each row means

### Reading the record

Browsing, searching, and inspecting artifacts, tokens, collections,
addresses, blocks, and transactions. This is the product's core and it is
read-only: nothing about reading requires a wallet.

### Creating and transferring

Each create page states, in one place before its first control, whether that
operation is open and what is holding it if not. The form appears only when
the deployment will accept the order it produces, so no control pretends an
action can finish when it cannot, and nothing is created, signed or broadcast
while a flow is closed.

The product publishes the same answer the pages read, one state per
operation, at `https://zrunes.io/api/readiness`. The create routes enforce
that exact state, so the page and the route cannot disagree.
[Details](/docs-zerdinals-and-zrunes/create/signing-availability/).

### ZRunes activation

The ZRunes protocol ignores mainnet data outputs below its activation height
by rule, so before that height nothing can be etched or minted and no ZRune
exists. This is a protocol fact that any independent node reading the chain
reproduces, not a setting on the product's side.

The product reads chain progress from its own indexer. Reaching activation
height is one prerequisite: creating or minting also requires current indexed
coverage, wallet signing qualification and operation readiness. Activation
alone does not establish that an operation can complete.
[The specification](/docs-zerdinals-and-zrunes/protocols/zrunes-v1/).

## How this snapshot is checked

The values above live in one data file in this repository. Build checks reject
missing fields and snapshots older than the permitted age. Passing those
checks does not query the current product or qualify a release. Updating the
snapshot requires fresh observations and matching screenshot provenance.
